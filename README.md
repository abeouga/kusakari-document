# Kusakari の文書

Kusakari EC と Kusakari Canvas の設計の図（ユースケース図・シーケンス図・クラス図・テーブル設計図）と、開発の記録を置くリポジトリです。
ソースのリポジトリ（kusakari-ec、kusakari-canvas）には、今の仕様の説明と設計判断（ADR）だけを置きます。
検証ログ・調査・日付ごとの経緯・採用しなかった試行は、ここに置きます。

## フォルダー

ルートは文書の種類ごとに分け、その中をリポジトリごとに分けます。

```
├─ ユースケース図/              アクターとユースケースの関係（00 に EC と Canvas の全体）
│  ├─ kusakari-canvas/
│  └─ kusakari-ec/
├─ シーケンス図/                ユースケースごとの処理の流れ（概要図と詳細図）
│  ├─ kusakari-canvas/
│  └─ kusakari-ec/
├─ クラス図/                    backend のクラスと、Canvas の画面のデータ型
│  ├─ kusakari-canvas/
│  └─ kusakari-ec/
├─ テーブル設計図/              マイグレーションから起こした ER 図とテーブル定義
│  ├─ kusakari-canvas/
│  └─ kusakari-ec/
├─ アーカイブ/                  以前のユースケース記述とシーケンス図（参照用。更新しません）
│  ├─ シーケンス図/             シーケンス図の書き方の資料と、EC-A01・EC-A02 のシーケンス図
│  └─ ユースケース/             ユースケース記述（kusakari-canvas/、kusakari-ec/）
├─ アーキテクチャ解説/          構成とデザインパターンの解説
├─ 日報/                        開発日報のページ
└─ 開発の記録/                  ソースのリポジトリから移した記録（機能ごと）
   ├─ kusakari-canvas/
   │  ├─ AI画像生成/
   │  ├─ 植物モデル/
   │  ├─ 写真と配置/            写真・カメラ推定・配置操作・画面構成・自動保存・寸法
   │  ├─ 買い物リストとEC連携/
   │  ├─ 認証/
   │  └─ 開発環境とDB/          セットアップ・DB の初期化・FastAPI への移行・E2E・SysOverRay・共通ヘッダー
   └─ kusakari-ec/
      ├─ DB構成/                DB の設計・移行の計画・ER 図の経緯・DB の初期化の検証
      ├─ 店舗と組織/
      ├─ 認証とアカウント/
      ├─ 商品とカート/          商品登録・植物モデルとの連携・カート・買い物リスト・店舗受け取り
      ├─ 機能要件と受け入れ試験/
      └─ 開発環境/              起動・停止・SysOverRay・デプロイ
```

Canvas の AWS 構成の文書は、kusakari-terraform の `docs/` にあります。

## 図を書き足すときの決まり

- 図は Mermaid で書きます。
  GitHub と Obsidian で表示できる書き方だけを使います。
- 図はコードから起こします。
  各ファイルの先頭に、元にしたリポジトリとコミットを書きます。
  コードが変わって図と食い違ったら、図を直してコミットを書き換えます。
- シーケンス図のファイル名は、ユースケース記述と同じ名前にします。
  書き方は `アーカイブ/シーケンス図/実装からシーケンス図を書く.html` に従います。
- テーブル設計図は、マイグレーション（EC は Flyway、Canvas は Alembic）を正にします。
- ソースのリポジトリ内へのリンクは、GitHub の URL（コミットつき）で書きます。
- `アーカイブ/` の文書は書き換えません。

## 開発の記録に書き足すときの決まり

- ファイル名は `YYYY-MM-DD_名前.md` にします。
  日付は記録の日付です。
  ソースから移した文書は、元の英語の名前をそのまま使います。
  元の文書から一部の節だけを移したときは、`_検証`、`_経緯` を付けます。
- ソースから移した文書は、先頭の見出しの直後に「元の場所：リポジトリ/パス（コミット）」を1行書きます。
- 記録なので、移した後に中身を今の仕様へ書き換えません。
  今の仕様は、ソースのリポジトリの文書を見てください。
- ソースのリポジトリ内へのリンクは、相対パスではなく GitHub の URL（コミットつき）で書きます。
- 実利用者の情報、秘密の値、PC ごとの設定は書きません。
