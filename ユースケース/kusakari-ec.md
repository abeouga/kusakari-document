#### EC-B12 商品を購入する

| 記述項目     | 記述内容                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| ユースケース概要 | 受取店舗と支払方法を指定して決済し、カート内の商品を注文する。                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |

| 事前条件     | ログイン状態である。<br>カートに商品が1つ以上存在する。                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| 事後条件     | 成功時は決済が完了し、注文が利用者のアカウントに紐づいて記録され、注文完了画面が表示される。<br>失敗時は決済・注文は行われず、カートの内容は維持される。                                                                                                                                                                                                                                                                                                                                                                                                                         |
| 基本フロー    | 1. 利用者がヘッダーのカートボタンを選ぶ。<br>2. システムがカート画面を表示する。<br>3. 利用者が受取店舗を1つ選ぶ。（位置情報の利用を許可した場合は距離順、許可しない場合は店舗一覧の順に候補が表示される）<br>4. 利用者が受取者名、電話番号、メールアドレスを入力する。<br>5. 利用者が支払方法を一覧から選択する。<br>6. 利用者が受取希望日と希望時間帯を入力する。<br>7. 利用者が注文内容確認を選ぶ。<br>8. システムが在庫と入力内容を確認し、注文内容（商品・受取店舗・支払合計）を表示する。<br>      在庫不足・在庫競合・入力不備がある場合は => 代替フロー1へ。<br>9. 利用者が注文確定を選ぶ。<br>10. システムが在庫を引き当て、支払合計で決済を実行する。<br>      決済に失敗した場合は => 代替フロー2へ。<br>11. システムが注文明細を保存し、カートを空にする。<br>      保存に失敗した場合は => 代替フロー3へ。<br>12. システムが注文完了画面に注文番号を表示する。 |
| 代替フロー    | 1. 在庫不足・在庫競合・入力不備がある場合<br>1-1. システムが注文を拒否し、該当する商品または入力項目を示してエラーメッセージを表示する。<br>1-2. 利用者がカートまたは入力内容を修正し、基本フロー7へ戻る。<br><br>2. 決済に失敗した場合<br>2-1. システムが引き当てた在庫を戻し、「決済に失敗しました」と理由（カード利用不可・残高不足・通信エラーなど）を表示する。<br>2-2. システムが入力内容を保持したまま支払方法の選択欄を表示する。<br>2-3. 利用者が支払方法を選び直し、基本フロー7へ戻る。<br><br>3. 保存に失敗した場合<br>3-1. システムが実行した決済を取り消し、引き当てた在庫を戻す。<br>3-2. システムが「注文失敗」を表示し、カートの内容を維持したまま再操作できるようにする。                                                                                                             |
| 関連情報     | カート内の商品が複数の出店者にまたがる場合も、受取店舗は1つにまとめる。まとめる方法は未決定。<br>保存した注文明細は注文履歴に表示される。                                                                                                                                                                                                                                                                                                                                                                                                                                |

#### EC-A10 商品を審査する

| 記述項目     | 記述内容                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| -------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| ユースケース概要 | 管理者が出店者の登録した商品の内容を確認し、承認または却下する。                                                                                                                                                                                                                                                                                                                                                                                                                    |
| アクター     | 管理者（運営者）                                                                                                                                                                                                                                                                                                                                                                                                                                            |

| 事後条件     | 対象商品の審査状態が「承認」または「却下」としてデータベースに保存され、出店者に審査結果が通知されている。                                                                                                                                                                                                                                                                                                                                                                                               |
| 基本フロー    | 1. 管理者が「商品審査」を選択する。<br>2. システムが審査状態が「審査中」の商品を取得する。<br>      通信エラーが発生した場合は => 代替フロー4へ<br>3. システムが審査待ち商品一覧（商品名、店舗名、申請日）を表示する。<br>      審査待ちの商品がない場合は => 代替フロー1へ<br>4. 管理者が審査対象の商品を選ぶ。<br>5. システムが商品の詳細（商品画像、商品名、カテゴリ、価格、商品説明、店舗名）と「承認する」「却下する」を表示する。<br>6. 管理者が商品の内容を確認し、「承認する」を選ぶ。<br>      却下する場合は => 代替フロー2へ<br>7. システムが商品の審査状態を「承認」に更新する。<br>      更新に失敗した場合は => 代替フロー3へ<br>8. システムが出店者に審査結果（承認）を通知する。<br>9. システムが審査完了メッセージを表示し、審査待ち商品一覧を再表示する。   |
| 代替フロー    | 1. 審査待ちの商品がない場合<br>1-1. システムが「審査待ちの商品はありません」と表示する。<br><br>2. 却下する場合<br>2-1. 管理者が「却下する」を選ぶ。<br>2-2. システムが却下理由の入力欄を表示する。<br>2-3. 管理者が却下理由を入力して確定する。<br>      却下理由が未入力の場合は、システムが却下理由の入力を求め、審査状態を変更しない。<br>2-4. システムが商品の審査状態を「却下」に更新する。<br>      更新に失敗した場合は => 代替フロー3へ<br>2-5. システムが出店者に審査結果（却下）と却下理由を通知し、基本フロー9へ進む。<br><br>3. 更新に失敗した場合<br>3-1. システムが更新エラーを表示し、審査状態を変更しない。<br>3-2. 基本フロー5へ戻る。<br><br>4. 通信エラーが発生した場合<br>4-1. システムが通信エラーを表示し、再取得を可能にする。 |
