#### EC-A11 店舗の利用を停止・再開する

| 記述項目 | 記述内容 |
| -------- | -------- |
| ユースケース概要 | 運営者が問題のある店舗の出店者に警告し、必要に応じて店舗の利用を停止する。問題が解消したら、警告を解除し、利用を再開する。 |
| アクター | 運営者 |
| 事前条件 | 運営者アカウントでログインしている。<br>「トップ」画面が表示されている。<br>対象の店舗が登録されていて、閉鎖済みではない。 |
| 事後条件 | 対象店舗が利用停止または利用可能として表示され、操作の履歴が残り、出店者に通知されている。 |
| 基本フロー | 1. 運営者が運営者画面のメニュー「店舗管理」を開く(EC-C02)。<br>2. システムが「店舗管理」画面に店舗の一覧と状態を表示する(EC-A05)。利用停止中でない店舗には、「警告する」ボタンと、「デンジャーエリア」に「利用を停止」ボタンを表示する。<br>3. 運営者が対象店舗の「デンジャーエリア」の「利用を停止」ボタンをクリックする。<br>4. システムが「利用停止の確認」ダイアログに、対象の店舗名、停止すると商品が購入者向けの画面に表示されなくなり出店者が商品・在庫・注文を操作できなくなること、確定済みの注文はキャンセルされないこと、「理由(必須・出店者に通知します)」入力欄を表示する。<br>5. 運営者が「理由」入力欄に理由を入力する。<br>6. 運営者が「利用停止を確定」ボタンをクリックする。<br>7. システムが店舗の状態を「運営により停止中」に更新し、操作の履歴を記録する。<br>8. システムが店舗の担当者へのイベント通知(EC-S11)で、「店舗の利用が停止されました」と店舗名・理由を通知する。<br>9. システムが「停止しました。出店者に通知しました。」と更新後の状態を表示し、「利用を停止」ボタンの代わりに「利用を再開」ボタンを表示する。 |
| 代替フロー | 3a. 停止せずに警告する場合<br>3a-1. 運営者が対象店舗の「警告する」ボタン(警告中の場合は「もう一度警告する」ボタン)をクリックする。<br>3a-2. システムが「警告の確認」ダイアログに、対象の店舗名、利用の状態は変わらないこと、「理由(必須・出店者に通知します)」入力欄を表示する。<br>3a-3. 運営者が理由を入力し、「警告する」ボタンをクリックする。<br>3a-4. システムが警告を履歴に記録し、イベント通知(EC-S11)で「店舗に運営から警告がありました」と店舗名・理由を通知する。<br>3a-5. システムが「警告しました。出店者に通知しました。」と表示し、店舗に「警告中」のバッジと理由を表示する。<br>3a-6. ユースケースを終了する。<br><br>3b. 警告を解除する場合<br>3b-1. 運営者が警告中の店舗の「警告を解除」ボタンをクリックする。<br>3b-2. システムが「警告の解除の確認」ダイアログに、対象の店舗名と「理由(任意・出店者に通知します)」入力欄を表示する。<br>3b-3. 運営者が必要に応じて理由を入力し、「警告を解除する」ボタンをクリックする。<br>3b-4. システムが警告の解除を履歴に記録し、イベント通知(EC-S11)で「店舗への運営の警告が解除されました」と通知する。<br>3b-5. システムが「警告を解除しました。出店者に通知しました。」と表示し、「警告中」のバッジを消す。<br>3b-6. ユースケースを終了する。<br><br>3c. 利用を再開する場合<br>3c-1. 運営者が利用停止中の店舗の「利用を再開」ボタンをクリックする。<br>3c-2. システムが「利用再開の確認」ダイアログに、対象の店舗名と「理由(任意・出店者に通知します)」入力欄を表示する。<br>3c-3. 運営者が必要に応じて理由を入力し、「利用再開を確定」ボタンをクリックする。<br>3c-4. システムが店舗の利用停止を解除して履歴に記録し、イベント通知(EC-S11)で「店舗の利用停止が解除されました」と通知する。<br>3c-5. システムが「再開しました。出店者に通知しました。」と更新後の状態を表示する。<br>3c-6. ユースケースを終了する。<br><br>3d. 履歴を確認する場合<br>3d-1. 運営者が対象店舗の「警告・停止の履歴」を開く。<br>3d-2. システムが警告・警告の解除・停止・再開の履歴を、新しい順に日時・操作した運営者・理由とともに表示する。履歴がなければ「履歴はありません。」を表示する。<br>3d-3. ユースケースを終了する。<br><br>5a. 理由が必須の操作(利用停止・警告)で、理由が未入力のまま確定した場合<br>5a-1. システムが「理由を入力してください。」を表示し、店舗の状態を変更しない。<br>5a-2. 基本フロー5へ戻る。<br><br>6a. 確認ダイアログで「取消」ボタンをクリックした場合<br>6a-1. システムがダイアログを閉じ、店舗の状態を変更せず「店舗管理」画面を表示する。<br>6a-2. ユースケースを終了する。<br><br>7a. 操作の前に店舗が閉鎖済みになっていた場合<br>7a-1. システムが「この店舗は閉鎖済みです。」を表示し、店舗の状態を変更しない。<br>7a-2. ユースケースを終了する。 |
| 関連情報 | ・共通代替フロー *b を適用する。<br>・閉鎖済みの店舗には、警告・利用停止・利用再開の操作を表示しない。閉鎖中の店舗にはできる。<br>・警告は利用停止の前に行ってもよい段階で、必ず行う必要はない。警告しても店舗の状態は変わらず、購入者への表示も注文の受付も続く。期限はなく、自動では停止しない。警告を解除できるのは運営者だけで、利用停止・再開をしても警告は自動では解除されない。<br>・利用停止中の店舗の商品は購入者向けの画面に表示せず、新しい注文も受け付けない(EC-B12)。カートに入っている商品は、カートを開いたときにカートから外す(EC-B08)。<br>・利用停止中の店舗の出店者は、商品・在庫・注文などの出店者向けの操作ができない。<br>・すでに確定した注文はキャンセルしない。利用停止中は注文の状態も更新できないため、受け渡しは利用を再開してから続ける。<br>・通知は、組織のオーナーと、その店舗でロールを割り振られた担当者に届く。<br>・警告中の状態と理由は、出店者の「店舗一覧」と「店舗プロフィール」画面にも表示される。購入者向けの画面には表示しない。<br>・理由は500文字まで入力できる。<br>・すでに利用停止中の店舗の停止、利用停止していない店舗の再開、警告していない店舗の警告の解除は、何もせず、履歴も通知も残さない。 |
