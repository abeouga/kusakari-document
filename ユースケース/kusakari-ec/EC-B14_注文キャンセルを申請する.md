#### EC-B14 注文キャンセルを申請する

| 記述項目     | 記述内容                                                                                                                                                            |
| -------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| ユースケース概要 | 対象注文について理由を入力し、キャンセル申請をする。                                                                                                                                      |
| アクター     | 購入者                                                                                                                                                        |
| 事前条件     | ログイン状態である。<br>注文履歴に注文が1件以上ある。                                                                                                                                                 |
| 事後条件     | キャンセル申請がキャンセル申請状態「申請中」として保存され、出店者に通知されている。<br>注文履歴にキャンセル申請状態(「申請中」)が表示されている。                                                                                       |
| 基本フロー    | 1. 購入者が対象注文の「注文のキャンセルを申請」を選ぶ。<br>2. システムがキャンセル理由の選択欄と詳細の入力欄、申請後は取り消せないことへの同意チェックを表示する。<br>3. 購入者が理由を選び、必要に応じて詳細を入力し、同意にチェックしてキャンセルを申請する。<br>4. システムがキャンセル申請を記録する。<br>5. システムが出店者にイベント通知(EC-S11)で申請を知らせる。<br>6. システムが注文履歴にキャンセル申請状態(「申請中」)を表示する。 |
| 代替フロー    | 1a. 申請対象外の注文の場合<br>1a-1. システムが、注文状態が「注文受付」以外の注文や、キャンセル申請状態が「申請中」の注文では申請操作を表示しない。「受取準備完了」の注文では、受取店舗へ問い合わせるよう案内する。<br>1a-2. ユースケースを終了する。<br><br>3a. 理由が未選択、または同意にチェックしていない場合<br>3a-1. システムが入力を求める表示をし、申請しない。<br>3a-2. 基本フロー3へ戻る。<br><br>3b. 申請をやめる場合<br>3b-1. 購入者が申請欄を閉じる。<br>3b-2. システムが申請せずに注文履歴を表示する。<br>3b-3. ユースケースを終了する。<br><br>4a. 申請前に注文状態が変わっていた場合(受取準備完了になったなど)<br>4a-1. システムが申請できないことを表示し、申請しない。<br>4a-2. ユースケースを終了する。 |
| 関連情報     | ・共通代替フロー *b を適用する。<br>・キャンセル申請は、注文の出店者がEC-S13で承認または却下する。<br>・申請の受付は出店者向けのイベント通知(EC-S11)で知らせる。<br>・処理結果(承認/却下)は利用者通知(EC-B15)で知らせる。却下の場合は店舗からの回答(却下理由)も通知に含める。<br>・承認されると注文は「キャンセル済み」になり、在庫が店舗に戻る。<br>・却下されたあとも、注文状態が「注文受付」であれば同じ注文について再び申請できる。 |
