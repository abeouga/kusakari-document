#### EC-B12 商品を購入する

| 記述項目     | 記述内容 |
| -------- | ---- |
| ユースケース概要 | 支払方法を指定し、カート内の商品を店舗受け取りで注文する。 |
| アクター     | 購入者 |
| 事前条件     | 購入者アカウントでログインしている。<br>カートに商品が1つ以上存在する。各商品の受取店舗は、商品が属する店舗である。<br>共通ヘッダーのある画面(「トップ」画面など)が表示されている。 |
| 事後条件     | 成功時は、受取店舗ごとの注文が注文状態「注文受付」で購入者のアカウントに紐づいて記録されている。また、在庫が減ってカートが空になり、購入者と出店者にサイト内通知が届き、「注文を保存しました」画面が表示されている。<br>失敗時は注文が行われず、カートの内容が維持されている。カードの支払いに失敗した場合は、注文が取り消されて在庫が戻っている。 |
| 基本フロー    | 1. 購入者が共通ヘッダーの「カート」リンクをクリックする。<br>2. システムが「ショッピングカート」画面に、商品ごとの受取店舗・数量・金額と「ご請求内容」を表示する(EC-B08)。<br>3. 購入者が「注文内容を確認する」ボタンをクリックする。<br>4. システムが最新のカートを取得し、「お支払い・受け取りの確認」画面に「受け取り店舗とご注文商品（N点）」(受取店舗ごとの店舗名・所在地・営業時間と商品)、「受け取る方」、「お支払い方法」、「ご請求内容」を表示する。「お支払い方法」は「店舗でお支払い」を選んだ状態で表示する。<br>5. 購入者が「お支払い方法」の一覧(「クレジットカード」「店舗でお支払い」)から「店舗でお支払い」を選択する。<br>6. 購入者が「注文を確定する」ボタンをクリックする。<br>7. システムがカートの内容・在庫・合計金額を確認して在庫を引き当て、受取店舗ごとに注文を注文状態「注文受付」で保存し、カートを空にする。<br>8. システムがサイト内通知で、購入者に「ご注文を受け付けました」、出店者に「新しい注文が届きました」(EC-S11)を知らせる。<br>9. システムが「注文を保存しました」画面に、注文ごとの注文番号・受取店舗・お支払い方法・ご注文商品・合計を表示する。店舗でお支払いの注文には「受け取り時に店頭でお支払いください。」と表示する。 |
| 代替フロー    | 2a. 在庫不足、または購入できない商品がある場合<br>2a-1. システムが該当する商品に「在庫不足（現在 N 点）」または「現在は購入できません」と表示し、「注文内容を確認する」ボタンを押せない状態にする。<br>2a-2. 購入者がカートを修正する(EC-B09、EC-B10)。<br>2a-3. 基本フロー2へ戻る。<br><br>4a. 最新のカートで在庫不足になっていた場合<br>4a-1. システムが該当する商品に「在庫不足（現在 N 点）」と表示し、「注文を確定する」ボタンを押せない状態にする。<br>4a-2. 購入者が「カートに戻る」ボタンをクリックする。<br>4a-3. 代替フロー2aへ進む。<br><br>5a. 「クレジットカード」を選択した場合<br>5a-1. 購入者が「お支払い方法」から「クレジットカード」を選択する。<br>5a-2. システムが「注文を確定する」ボタンの表示を「注文してカードで支払う」に変える。<br>5a-3. 購入者が「注文してカードで支払う」ボタンをクリックする。<br>5a-4. システムがカートの内容・在庫・合計金額を確認して在庫を引き当て、受取店舗ごとに注文を注文状態「支払い待ち」で保存し、カートを空にする。<br>5a-5. システムが「カードでのお支払い」画面に、お支払い金額(受取店舗ごとの注文 N 件の合計)、決済会社(Stripe)のカード情報の入力欄、「(金額)を支払う」ボタンを表示する。<br>5a-6. 購入者がカード情報を入力し、「(金額)を支払う」ボタンをクリックする。<br>5a-7. システムがカード情報を決済会社へ送って支払いを行い、「支払いを確認しています」と表示する。<br>5a-8. システムが決済会社から支払い成功の連絡を受け、受取店舗ごとの注文の注文状態を「注文受付」に更新する。<br>5a-9. 基本フロー8へ進む。完了画面のカードの注文には「カードでのお支払いを確認しました（テストモードのため実際の請求はありません）。」と表示する。<br><br>5b. カード情報の入力に不備がある場合(5a-6の後)<br>5b-1. システムが決済会社のエラーメッセージを表示し、支払いを行わない。<br>5b-2. 代替フロー5a-6へ戻る。<br><br>5c. カードが断られるなど、支払いに失敗した場合(5a-7の後)<br>5c-1. システムが注文を取り消して在庫を戻し、購入者にサイト内通知「ご注文を取り消しました」を送る。<br>5c-2. システムが「お支払いができなかったため、注文を取り消しました。商品の在庫は元に戻しています。」と「商品を探す」ボタンを表示する。<br>5c-3. ユースケースを終了する。<br><br>5d. 支払いの確認に時間がかかる場合(5a-7の後)<br>5d-1. システムが「お支払いの確認に時間がかかっています。注文の状態は購入履歴で確認できます。」と「購入履歴を開く」ボタンを表示する。<br>5d-2. ユースケースを終了する。支払いの結果は注文履歴(EC-B13)に反映される。<br><br>5e. 支払い待ちのまま30分が過ぎた場合(5a-5の後に支払わなかったなど)<br>5e-1. システムが注文を取り消して在庫を戻し、購入者にサイト内通知「ご注文を取り消しました」(お支払いの期限が過ぎたため)を送る。<br>5e-2. ユースケースを終了する。<br><br>5f. 決済会社との通信に失敗した場合(5a-4の後)<br>5f-1. システムが「カード決済の処理に失敗しました。時間をおいてもう一度お試しください。」と表示する。注文は「支払い待ち」のまま残る。<br>5f-2. 購入者が「注文してカードで支払う」ボタンをもう一度クリックすると、同じ注文の支払いをやり直し、代替フロー5a-5へ進む。やり直さなければ、30分後に代替フロー5eへ進む。<br><br>7a. 別の操作でカートが更新されていた場合<br>7a-1. システムが注文を保存せず、「別の操作でカートが更新されました。最新の内容を確認してください。」と表示して、最新のカートで確認画面を表示する。<br>7a-2. 基本フロー5へ戻る。<br><br>7b. カートに入れた後に商品の価格が変わっていた場合<br>7b-1. システムが注文を保存せず、「価格が変更されました。合計金額を確認してください。」と表示して、最新の価格で確認画面を表示する。<br>7b-2. 基本フロー5へ戻る。<br><br>7c. 在庫の引き当てに失敗した場合(直前に他の購入者が購入した場合など)<br>7c-1. システムが注文も在庫の減算も保存せず、「在庫が変更されました。数量を変更してください。」と表示する。<br>7c-2. システムが最新のカートと在庫を表示し、「注文を確定する」ボタンを押せない状態にする。<br>7c-3. 購入者が「カートに戻る」ボタンをクリックする。<br>7c-4. 代替フロー2aへ進む。<br><br>7d. 受取店舗が新しい注文を受け付けていない場合(店舗の閉鎖中・非公開・利用停止、組織の受付停止など)<br>7d-1. システムがどの注文も保存せず、「(店舗名)は受付を停止しています。」と表示する。<br>7d-2. 購入者が「カートに戻る」ボタンをクリックする。<br>7d-3. 購入者が該当する商品をカートから削除する(EC-B10)。<br>7d-4. 基本フロー2へ戻る。<br><br>7e. 運営者に公開停止された商品がカートにあった場合<br>7e-1. システムが注文を保存せず、「購入できない商品があります。カートを確認してください。」と表示する。<br>7e-2. 購入者が「カートに戻る」ボタンをクリックする。<br>7e-3. 代替フロー2aへ進む。<br><br>7f. カード決済が使えなくなっていた場合(5a-4で)<br>7f-1. システムが注文を保存せず、「カード決済は現在使えません。店頭払いを選んでください。」と表示する。<br>7f-2. 基本フロー5へ戻る。<br><br>7g. 保存に失敗した場合<br>7g-1. システムが注文も在庫の減算も保存せず、「保存処理を完了できませんでした。時間をおいて再試行してください。」と表示する。<br>7g-2. システムがカートの内容を維持したまま、「注文を確定する」ボタンを再びクリックできるようにする。<br>7g-3. ユースケースを終了する。 |
| 関連情報     | ・共通代替フロー *b を適用する。<br>・受取店舗は商品ごとに決まっている(商品が属する店舗。EC-B07)。購入手続きの中では選ばない。<br>・カートに複数の受取店舗の商品がある場合は、受取店舗ごとに注文を分けて保存し、それぞれの店舗の在庫から引き当てる。完了画面には「受取店舗ごとにN件の注文に分けて保存しました。」と表示する。受取店舗のうち1つでも新しい注文を受け付けていなければ、どの注文も保存しない。<br>・受取料金は無料とする。<br>・受取連絡先(お名前・電話番号・連絡先)はアカウントに登録した内容を使う。確認画面の「受取連絡先を変更」から変更できる。登録は任意で、未登録でも店頭で注文番号を伝えれば受け取れる。<br>・受取希望日時は指定しない。受け取りの準備ができたら利用者通知(EC-B15)で知らせる(EC-S09)。<br>・支払方法は「クレジットカード」と「店舗でお支払い」の2つである。<br>　- クレジットカード：決済会社(Stripe)のテストモードで支払う。実際の請求は発生しない。カード情報は決済会社の入力欄から決済会社へ直接送られ、このサイトのサーバーを通らない。決済の設定(鍵)がそろっていない環境では、選択肢に表示しない。注文が複数の受取店舗に分かれても、支払いは1回で、金額は全注文の合計である。<br>　- 店舗でお支払い：受け取り時に店頭で支払う。このサイトでは支払いを扱わず、注文は確定した時点で「注文受付」になる。<br>・カードの支払い待ちの注文は、保存した時点で在庫を確保する。30分以内に支払いが確認できなければ取り消し、在庫を戻す。画面での支払いの完了ではなく、決済会社からの連絡で「注文受付」にする。<br>・「注文を確定する」を続けて押したり、保存失敗の後に再試行したりしても、同じ注文は1回だけ記録する。<br>・保存した注文は注文履歴(EC-B13)に表示される。<br>・注文状態は「支払い待ち」(カードのみ)→「注文受付」→「受取準備完了」(EC-S09)→「引き渡し完了」(EC-S10)と進む。キャンセル申請が承認されると「キャンセル」(EC-S13)になり、カードで支払い済みの注文は返金する。<br>・注文には販売手数料の率と額を記録する(購入者には表示しない。EC-S07)。<br>・在庫の引き当てでは、同じ在庫を同時に引き当てないようにしてから数量を確認する。不足する場合は在庫不足として扱い、注文も在庫の減算も保存しない。<br>・店舗側のアカウント(出店者のオーナー・担当者)と出店申請用アカウントでは購入できない(EC-B07)。 |
