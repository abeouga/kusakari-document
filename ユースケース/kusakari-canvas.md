## 0. 全ユースケース共通の代替フロー

各ユースケースの基本フローのうち、システムがサーバーと通信するステップすべてに適用する。
個別の代替フローに同じ条件が書かれている場合は、個別の記述を優先する。

| ID  | 条件                    | 処理                                                                                               |
| --- | --------------------- | ------------------------------------------------------------------------------------------------ |
| *a  | 通信に失敗した場合             | *a-1. システムが通信エラーを表示する。<br>*a-2. システムが入力内容を保持したまま、再実行を可能にする。<br>*a-3. 利用者が再実行を選ぶと、失敗したステップから再開する。 |
| *b  | 未ログインの場合（ログイン必須のUCのみ） | *b-1. システムがログイン画面を表示する。<br>*b-2. 利用者がログインすると、元のステップへ戻る。                                          |

#### UC-01 庭プロジェクトを新規作成する

| 記述項目     | 記述内容                                                                                                                                                                    |
| -------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| ユースケース概要 | 庭シミュレーションを始めるために、新しい庭プロジェクトを作成する。                                                                                                                                       |
| アクター     | 利用者(購入者)                                                                                                                                                                |
| 事前条件     | 庭プロジェクト一覧画面が表示されている。                                                                                                                                                    |
| 事後条件     | 新しい庭プロジェクトが作成され、庭シミュレーション画面が表示されている。                                                                                                                                    |
| 基本フロー    | 1. 利用者が庭プロジェクト一覧画面で庭プロジェクトの新規作成を選ぶ。<br>2. 利用者が庭プロジェクト名を入力する。<br>3. システムが入力内容を検証し、庭プロジェクトを作成する。<br>4. システムが作成した庭シミュレーション画面を表示する。                                         |
| 代替フロー    | 3a. 入力内容が無効の場合(名前が空、文字数超過など)<br>3a-1. システムが入力エラーメッセージを表示し、プロジェクトを作成しない。<br>3a-2. 基本フロー2へ戻る。 |
| 関連情報     | ・共通代替フロー *a を適用する（ステップ3）。<br>・作成した庭プロジェクトを保存するときはログインが必須である。 |

#### UC-02 庭の写真をアップロードする

| 記述項目     | 記述内容                                                                                                                                                                                                              |
| -------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| ユースケース概要 | シミュレーションの土台にするため、実際の庭の写真を1枚アップロードする。                                                                                                                                                                              |
| アクター     | 利用者(購入者)                                                                                                                                                                                                          |
| 事前条件     | 庭プロジェクトが作成されている。<br>庭シミュレーション画面が表示されている。                                                                                                                                                                          |
| 事後条件     | 庭写真が庭プロジェクトに紐づいて登録され、庭シミュレーション画面に表示されている。                                                                                                                                                                         |
| 基本フロー    | 1. 利用者が庭シミュレーション画面で写真のアップロードを選ぶ。<br>2. 利用者が庭の写真を選択する。<br>3. システムが写真の形式・サイズを検証する。<br>4. システムが庭写真を庭プロジェクトに登録し、画面に表示する。<br>5. システムが施工範囲の指定を開始する。                                                                     |
| 代替フロー    | 3a. 写真の形式やサイズが不正な場合<br>3a-1. システムが対応形式・容量上限を示すエラーメッセージを表示し、登録しない。<br>3a-2. 基本フロー2へ戻る。 |
| 関連情報     | ・共通代替フロー *a を適用する（ステップ4）。<br>・登録できる庭写真は1プロジェクトにつき1枚とする。<br>・「写真を外す」ボタンをクリックすると写真が外れて、再度写真のアップロードが可能になる。<br>・写真を外すと施工範囲と実寸補正はリセットされるが、庭オブジェクトの配置情報は保存される。新しい施工範囲を確定したあと、範囲外になった庭オブジェクトには範囲外であることを表示する。<br>・対応形式・容量上限は別途定める(例: JPEG・PNG、10MB以下)。 |

#### UC-03 施工範囲を指定・修正する

| 記述項目     | 記述内容                                                                                                                                                                                                                                        |
| -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| ユースケース概要 | 庭写真上で施工したい範囲を線で結んで指定し、必要に応じて修正する。                                                                                                                                                                                                           |
| アクター     | 利用者(購入者)                                                                                                                                                                                                                                    |
| 事前条件     | 庭シミュレーション画面が表示されている。<br>庭写真がアップロードされている。                                                                                                                                                                                                    |
| 事後条件     | 施工範囲が庭プロジェクトに保存されている。                                                                                                                                                                                                                       |
| 基本フロー    | 1. 庭写真のアップロード後に、システムが施工範囲の指定を始める(または、利用者が施工範囲の指定を選ぶ)。<br>2. 利用者が庭写真上の点を順に指定し、線で結ぶ。<br>3. 利用者が範囲を閉じて確定する。<br>4. システムが範囲の形状を検証し、施工範囲として保存する。<br>5. システムが実寸の定義を案内する。<br>6. 利用者が範囲を修正したい場合、点を移動するか、「施工範囲を指定し直す」を選ぶ。<br>7. システムが修正後の範囲を検証し、更新する。 |
| 代替フロー    | 4a. 範囲が成立しない場合(点が3つ未満、線が交差するなど)<br>4a-1. システムがエラーメッセージを表示し、確定させない。<br>4a-2. 基本フロー2へ戻る。 |
| 関連情報     | ・共通代替フロー *a を適用する（ステップ4, 7）。 |

#### UC-04 施工範囲の実寸を定義する

| 記述項目     | 記述内容                                                                                                                                                                                                                                                                                |
| -------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| ユースケース概要 | 施工範囲の辺のうち1本の実際の長さを入力し、シミュレーション上の縮尺(実寸)を補正する。                                                                                                                                                                                                                                        |
| アクター     | 利用者(購入者)                                                                                                                                                                                                                                                                            |
| 事前条件     | 庭シミュレーション画面が表示されている。<br>施工範囲が確定している。                                                                                                                                                                                                                                                |
| 事後条件     | 実寸補正の情報(基準にした辺と長さ、算出した縮尺)が庭プロジェクトに保存されている。                                                                                                                                                                                                                                          |
| 基本フロー    | 1. システムが施工範囲の確定後に実寸の入力を案内する(または、利用者が実寸の定義を選ぶ)。<br>2. 利用者が施工範囲の辺を1本選ぶ。<br>3. 利用者がその辺の実際の長さを入力する。<br>4. システムが入力値を検証する。<br>5. システムが入力値から写真の縮尺を算出し、庭プロジェクトに保存する。<br>6. システムが補正後の縮尺を庭シミュレーションに反映する。                                                                                      |
| 代替フロー    | 1a. 実寸補正を行わない場合<br>1a-1. システムは実寸補正の情報を保存せず、施工範囲を囲む長方形を庭の幅×奥行き（土台寸法）に当てはめて写真と庭を対応付ける。<br>1a-2. ユースケースを終了する。<br><br>4a. 長さが無効な場合(0以下、数値以外、上限超過)<br>4a-1. システムが入力エラーメッセージを表示し、再入力を求める。<br>4a-2. 基本フロー3へ戻る。 |
| 関連情報     | ・共通代替フロー *a を適用する（ステップ5）。<br>・補正未設定の場合は、庭オブジェクトの大きさが実寸と合わない可能性がある。<br>・実寸定義は後からやり直せる。<br>・長さの単位はメートルとする。<br>・補正なしの場合は写真の遠近(奥ほど小さく写ること)を考慮しないため、面積や長さは「カメラ未設定・土台寸法からの概算」、写真の表示では「概算」と表示する。<br>・全辺入力後に点を動かすと、縮尺はそのままで、各辺の長さが新しい形に合わせて計算し直される（入力値は置き換わる）。 |

#### UC-05 庭オブジェクトを配置・編集する

| 記述項目     | 記述内容                                                                                                                                                                                                                                                                                                                                                            |
| -------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| ユースケース概要 | 植物や庭用品などの庭オブジェクトを庭に設置し、移動・回転・拡大縮小・削除して配置を考える。                                                                                                                                                                                                                                                                                                                   |
| アクター     | 利用者(購入者)                                                                                                                                                                                                                                                                                                                                                        |
| 事前条件     | 庭シミュレーション画面が表示されている。<br>庭写真がアップロードされ、施工範囲が設定されている。                                                                                                                                                                                                                                                                                                              |
| 事後条件     | 庭オブジェクトの位置・向き・大きさ・個数が庭シミュレーション上に反映されている。                                                                                                                                                                                                                                                                                                                        |
| 基本フロー    | 1. 利用者が設置したい商品を選ぶ。<br>2. 利用者が庭写真上の位置を指定して設置する。<br>3. システムが庭オブジェクトを庭シミュレーションに表示する。<br>4. 利用者が設置済みオブジェクトを選び、移動・回転・拡大縮小のいずれかを行う。<br>5. システムが操作結果を庭シミュレーションに反映する。<br>6. 利用者が不要なオブジェクトを選び、削除する。<br>7. システムが庭オブジェクトを庭シミュレーションから取り除く。                                                                                                                                  |
| 代替フロー    | 2a. 施工範囲の外に設置した場合<br>2a-1. システムが範囲外であることを表示して設置を反映せず、範囲内への配置を促す。<br>2a-2. 基本フロー2へ戻る。<br><br>4a. 施工範囲の外に移動した場合<br>4a-1. システムが範囲外であることを表示して移動を反映せず、範囲内への配置を促す。<br>4a-2. 基本フロー4へ戻る。<br><br>5a. 移動・拡大縮小で上限・下限を超える場合<br>5a-1. システムが上限・下限の位置・大きさに制限する。<br>5a-2. 基本フロー6へ進む。 |
| 関連情報     | ・共通代替フロー *a を適用する（ステップ2）。<br>・商品と似たモデル(庭オブジェクト)が庭シミュレーション上に設置される。<br>・商品と庭オブジェクトは1対1で紐づいている。<br>・庭オブジェクトは3Dモデルとして庭写真の上に配置する。<br>・庭写真を取り除き、施工範囲部分の3D土台だけを表示するタブがある。<br>・設置できる商品は、審査状態が「承認」かつ販売状態が「販売中」の商品だけとする。 |

#### UC-06 完成イメージ画像を生成・保存する

| 記述項目     | 記述内容                                                                                                                                                                              |
| -------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| ユースケース概要 | 配置した庭オブジェクトを元の庭写真に重ねた、完成イメージ画像を生成して確認・保存する。                                                                                                                                       |
| アクター     | 利用者(購入者)                                                                                                                                                                          |
| 事前条件     | 庭シミュレーション画面が表示されている。<br>庭オブジェクトが1つ以上配置されている。                                                                                                                                      |
| 事後条件     | 完成イメージ画像が生成され、利用者が確認・保存できる状態になっている。                                                                                                                                               |
| 基本フロー    | 1. 利用者が完成イメージの確認を選ぶ。<br>2. システムが配置情報(位置・向き・大きさ)を取得する。<br>3. システムが元の庭写真に庭オブジェクトを重ねて画像を生成する。<br>4. システムが完成イメージ画像を表示する。<br>5. 利用者が必要に応じて「PNGで保存」を選び、完成イメージ画像をPNG形式で端末に保存(ダウンロード)する。  |
| 代替フロー    | 3a. 生成に失敗した場合(処理エラー、通信失敗)<br>3a-1. システムがエラーを表示し、再生成を可能にする。<br>3a-2. 基本フロー3へ戻る。<br><br>5a. 保存に失敗した場合(ダウンロードできない、容量不足など)<br>5a-1. システムが保存に失敗したことを表示し、再実行を可能にする。<br>5a-2. 基本フロー5へ戻る。 |
| 関連情報     | ・共通代替フロー *a を適用する（ステップ2）。 |

#### UC-07 庭プロジェクトを保存する

| 記述項目     | 記述内容                                                                                                                                                                                                                                                                                                                                                                                                                           |
| -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| ユースケース概要 | 庭写真・施工範囲・実寸補正の情報と、庭オブジェクトの位置・向き・大きさ・個数・商品の情報を庭プロジェクトとして保存する。                                                                                                                                                                                                                                                                                                                                                                   |
| アクター     | 利用者(購入者)                                                                                                                                                                                                                                                                                                                                                                                                                       |
| 事前条件     | 庭シミュレーション画面が開かれている。                                                                                                                                                                                                                                                                                                                                                                                                            |
| 事後条件     | 庭写真・施工範囲・実寸補正の情報と、庭オブジェクトの位置・向き・大きさ・個数・商品の情報が保存され、次回以降に再開できる状態になっている。                                                                                                                                                                                                                                                                                                                                                          |
| 基本フロー    | 1. 利用者が庭オブジェクトの配置・編集や施工範囲の修正・実寸定義の操作を行う。<br>2. システムが庭写真・施工範囲・実寸補正の情報と、庭オブジェクトの位置・向き・大きさ・個数・商品の情報を取得する。<br>3. システムが取得した内容を庭プロジェクトとして自動保存する。<br>4. システムが保存完了を表すアイコンを表示する。                                                                                                                                                                                                                                                        |
| 代替フロー    | 1a. 未ログイン状態の場合<br>1a-1. システムが自動保存を行わず、「保存」ボタンを表示する。<br>1a-2. 利用者が「保存」ボタンを選ぶ。<br>1a-3. システムがログイン画面を表示する。<br>1a-4. 利用者がログインする。<br>1a-5. システムが編集内容を保持したまま、以降は自動保存を有効にする。<br>1a-6. 基本フロー2へ進む。<br><br>1a-4a. ログインを取り消した場合<br>1a-4a-1. システムが保存せずに庭シミュレーション画面に戻り、編集内容と「保存」ボタンの表示を維持する。<br>1a-4a-2. ユースケースを終了する。<br><br>3a. 通信に失敗した場合<br>3a-1. システムが通信エラーを表示し、保存されていないことを伝える。<br>3a-2. システムが編集内容を保持したまま、再保存を可能にする。<br>3a-3. 基本フロー3へ戻る。 |
| 関連情報     | ・共通代替フロー *a を適用する（ステップ2）。<br>・ログイン状態では自動保存、未ログイン状態では「保存」ボタンによる保存とする。<br>・未ログイン時の編集内容は保存されないため、画面を閉じると失われる。<br>・保存せず画面を閉じようとしたら「保存されていません」と警告メッセージを表示する。 |

#### UC-08 庭プロジェクトを管理する

| 記述項目     | 記述内容                                                                                                                                                                                                                                                                                                 |
| -------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| ユースケース概要 | 作成した庭プロジェクトを一覧で確認し、複製して別案を作ったり、不要なプロジェクトを削除したりする。                                                                                                                                                                                                                                                    |
| アクター     | 利用者(購入者)                                                                                                                                                                                                                                                                                             |
| 事前条件     | 利用者がログイン済みである。                                                                                                                                                                                                                                                                                       |
| 事後条件     | 複製した場合は新しい庭プロジェクトが追加され、削除した場合は対象が庭一覧から消えている。                                                                                                                                                                                                                                                         |
| 基本フロー    | 1. 利用者が庭プロジェクト一覧画面を開く。<br>2. システムが利用者の庭プロジェクトを一覧表示する。<br>3. 利用者がプロジェクトを選び、操作(「開く」「複製」「削除」)を選ぶ。<br>4. 「開く」の場合、システムが選択したプロジェクトの庭シミュレーション画面を表示する。<br>5. 「複製」の場合、システムが選択したプロジェクトの内容を複製し、「元の名前(コピー)」という名前で新規プロジェクトを作成して一覧に追加する。<br>6. 「削除」の場合、システムが削除の確認を表示する。利用者が確定すると、システムがプロジェクトを削除する。                 |
| 代替フロー    | 2a. 庭プロジェクトがない場合<br>2a-1. システムが新規作成(UC-01)を案内する。<br>2a-2. ユースケースを終了する。<br><br>6a. 削除を取り消した場合<br>6a-1. システムが削除せず、一覧表示に戻る。<br>6a-2. 基本フロー3へ戻る。 |
| 関連情報     | ・共通代替フロー *a を適用する（ステップ2, 5, 6）。<br>・共通代替フロー *b を適用する。<br>・複製は別案の比較に使う。<br>・削除したプロジェクトの復元はしない。(要確認) |

#### UC-09 買い物リストを表示する

| 記述項目     | 記述内容                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| ユースケース概要 | 庭シミュレーション画面のサイドバーに、配置した庭オブジェクトに紐づく商品を買い物リストとして表示し、必要に応じてECの買い物リストを開く。                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| アクター     | 利用者(購入者)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| 事前条件     | 庭シミュレーション画面が表示されている。                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| 事後条件     | サイドバーに、配置中の庭オブジェクトに紐づく商品の一覧(商品画像、商品名、数量、小計)が表示されている。                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| 基本フロー    | 1. システムが庭プロジェクトに配置されている庭オブジェクトとその個数を取得する。<br>2. システムが各庭オブジェクトに紐づく商品の情報をECから取得する。<br>3. システムが商品ごとに、商品画像、商品名、数量(配置数)、小計(価格×数量)をサイドバーに一覧表示する。<br>4. 利用者が庭オブジェクトを設置・削除した場合、システムが買い物リストの数量・小計を更新する。<br>5. 利用者が「ECの買い物リストを開く」を選ぶ。<br>6. システムが対象の庭プロジェクトを指定して、ECの買い物リストを開く。                                                                                                                                                                                                                                                           |
| 代替フロー    | 1a. 配置されたオブジェクトがない場合<br>1a-1. システムが買い物リストが空であることを表示し、オブジェクトの配置(UC-05)を案内する。<br>1a-2. ユースケースを終了する。<br><br>2a. 紐づく商品が存在しない場合(商品の削除、紐づけ解除など)<br>2a-1. システムがその庭オブジェクトに対応する商品がないことを一覧上に表示し、小計の計算から除外する。<br>2a-2. 基本フロー3へ進む。<br><br>5a. 未ログインの場合<br>5a-1. システムがログインを促す。<br>5a-2. 利用者がログインする。<br>5a-3. 基本フロー5へ戻る。<br><br>5b. 庭プロジェクトが保存中の場合<br>5b-1. システムが「ECの買い物リストを開く」を選べないようにする。<br>5b-2. 自動保存が完了したら、システムが「ECの買い物リストを開く」を選べるようにする。<br>5b-3. 基本フロー5へ戻る。 |
| 関連情報     | ・共通代替フロー *a を適用する（ステップ1, 2）。<br>・庭オブジェクトと商品は1対1で紐づく。<br>・数量は配置されている庭オブジェクトの個数とする。<br>・Canvasの買い物リストからはカートへ追加できない(カート追加はEC側の買い物リストのみ)。<br>・未ログインからログインしたとき、まだ保存していない庭プロジェクトをどう扱うか(保存してからECの買い物リストを開くかなど)は未定。(要確認) |
