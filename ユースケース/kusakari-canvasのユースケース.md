#### UC-01 庭プロジェクトを新規作成する

| 記述項目     | 記述内容                                                                                                                                                                              |
| -------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| ユースケース概要 | 庭シミュレーションを始めるために、新しい庭プロジェクトを作成する。                                                                                                                                                 |
| アクター     | 利用者(購入者)                                                                                                                                                                          |
| 事前条件     | 庭プロジェクト一覧画面が表示されている。                                                                                                                                                              |
| 事後条件     | 新しい庭プロジェクトを作成し、庭シミュレーション画面が表示される。                                                                                                                                                 |
| 基本フロー    | 1. 利用者が庭プロジェクト一覧画面で庭プロジェクトの新規作成を選ぶ。<br>2. 利用者が庭プロジェクト名を入力する。<br>3. システムが入力内容を検証し、庭プロジェクトを作成する。<br>入力内容が無効の場合は => 代替フロー1へ<br>通信に失敗した場合は => 代替フロー2へ<br>4. システムが作成した庭シミュレーション画面を表示する |
| 代替フロー    | 1. 入力内容が無効の場合(名前が空、文字数超過など)<br>1-1. システムが入力エラーメッセージを表示し、プロジェクトを作成しない。<br><br>2. 通信に失敗した場合<br>2-1. システムが通信エラーを表示し、再実行を可能にする。                                                       |
| 関連情報     | 作成した庭プロジェクトを保存するときはログイン必須。                                                                                                                                                        |

#### UC-02 庭の写真をアップロードする

| 記述項目     | 記述内容                                                                                                                                                                                                           |
| -------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| ユースケース概要 | シミュレーションの土台にするため、実際の庭の写真を1枚アップロードする。                                                                                                                                                                           |
| アクター     | 利用者(購入者)                                                                                                                                                                                                       |
| 事前条件     | 庭プロジェクトが作成されている。庭シミュレーション画面が表示されている。                                                                                                                                                                           |
| 事後条件     | 庭写真が庭プロジェクトに紐づいて登録され、庭シミュレーション画面に表示される。                                                                                                                                                                        |
| 基本フロー    | 1. 利用者が庭シミュレーション画面で写真のアップロードを選ぶ。<br>2. 利用者が庭の写真を選択する。<br>3. システムが写真の形式・サイズを検証する。<br>      形式やサイズが不正な場合は => 代替フロー1へ<br>4. システムが庭写真を庭プロジェクトに登録し、画面に表示する。<br>      通信に失敗した場合は => 代替フロー2へ<br>5. システムが施工範囲の指定を開始する。 |
| 代替フロー    | 1. 写真の形式やサイズが不正な場合<br>1-1. システムが対応形式・容量上限を示すエラーメッセージを表示し、登録しない。<br><br>2. 通信に失敗した場合<br>2-1. システムが通信エラーを表示し、再実行を可能にする。                                                                                          |
| 関連情報     | 登録できる庭写真は1プロジェクトにつき1枚。 / 写真を外すボタンをクリックすると写真が外れて再度写真のアップロードが可能になる。写真を外すと施工範囲はリセットされるが、庭オブジェクトの配置情報は保存される / 対応形式・容量上限は別途定める(例：JPEG・PNG、10MB以下)。                                                                  |

#### UC-03 施工範囲を指定・修正する

| 記述項目     | 記述内容                                                                                                                                                                                                                                                                                                    |
| -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| ユースケース概要 | 庭写真上で施工したい範囲を線で結んで指定し、必要に応じて修正する。                                                                                                                                                                                                                                                                       |
| アクター     | 利用者(購入者)                                                                                                                                                                                                                                                                                                |
| 事前条件     | 庭シミュレーション画面が表示されている。庭写真がアップロードされている。                                                                                                                                                                                                                                                                    |
| 事後条件     | 施工範囲が庭プロジェクトに保存される。                                                                                                                                                                                                                                                                                     |
| 基本フロー    | 1. 利用者が庭写真をアップロード後、システムが施工範囲の指定を始める。（または、施工範囲の指定を選ぶ。）<br>2. 利用者が庭写真上の点を順に指定し、線で結ぶ。<br>3. 利用者が範囲を閉じて確定する。<br>4. システムが範囲の形状を検証し、施工範囲として保存する。<br>      範囲が成立しない場合は => 代替フロー1へ<br>      通信に失敗した場合は => 代替フロー2へ<br>5. システムが実寸の定義を案内する<br>6. 利用者が範囲を修正したい場合、点を移動または、施工範囲を指定し直すを選ぶ。<br>7. システムが修正後の範囲を検証し、更新する。 |
| 代替フロー    | 1. 範囲が成立しない場合(点が3つ未満、線が交差するなど)<br>1-1. システムがエラーメッセージを表示し、確定させない。<br><br>2. 通信に失敗した場合<br>2-1. システムが通信エラーを表示し、再実行を可能にする。                                                                                                                                                                                  |
| 関連情報     |                                                                                                                                                                                                                                                                                                         |

#### UC-04 施工範囲の実寸を定義する

| 記述項目     | 記述内容                                                                                                                                                                                                                                                                                          |
| -------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| ユースケース概要 | 施工範囲の辺のうち1本の実際の長さを入力し、シミュレーション上の縮尺(実寸)を補正する。                                                                                                                                                                                                                                                  |
| アクター     | 利用者(購入者)                                                                                                                                                                                                                                                                                      |
| 事前条件     | 庭シミュレーション画面が表示されている。施工範囲が確定している。                                                                                                                                                                                                                                                              |
| 事後条件     | 実寸補正の情報(基準にした辺と長さ、算出した縮尺)が庭プロジェクトに保存される。                                                                                                                                                                                                                                                      |
| 基本フロー    | 1. システムが施工範囲の確定後に実寸の入力を案内する。(または、利用者が実寸の定義を選ぶ。)<br>      実寸補正を行わない場合は => 代替フロー3へ<br>2. 利用者が施工範囲の辺を1本選ぶ。<br>3. 利用者がその辺の実際の長さを入力する。<br>4. システムが入力値を検証する。<br>      長さが無効な場合は => 代替フロー1へ<br>5. システムが入力値から写真の縮尺を算出し、庭プロジェクトに保存する。<br>      通信に失敗した場合は => 代替フロー2へ<br>6. システムが補正後の縮尺を庭シミュレーションに反映する。 |
| 代替フロー    | 1. 長さが無効な場合(0以下、数値以外、上限超過)<br>1-1. システムが入力エラーメッセージを表示し、再入力を求める。<br><br>2. 通信に失敗した場合<br>2-1. システムが通信エラーを表示し、再実行を可能にする。<br><br>3. 実寸補正を行わない場合<br>3-1. システムが補正なし(標準縮尺)として実寸補正の情報を保存する。                                                                                                           |
| 関連情報     | 補正未設定の場合は、庭オブジェクトの大きさが実寸と合わない可能性がある。 / 実寸定義は後からやり直せる。 / 長さの単位はメートル。 / 実寸定義の後に施工範囲の点を動かすと、基準にした辺の長さが変わり、縮尺がずれるので**要確認**。                                                                                                                                                                       |

#### UC-05 庭オブジェクトを配置・編集する

| 記述項目     | 記述内容                                                                                                                                                                                                                                                                                                                               |
| -------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| ユースケース概要 | 植物や庭用品などの庭オブジェクトを庭に設置し、移動・回転・拡大縮小・削除して配置を考える。                                                                                                                                                                                                                                                                                      |
| アクター     | 利用者(購入者)                                                                                                                                                                                                                                                                                                                           |
| 事前条件     | 庭シミュレーション画面が表示されている。庭写真がアップロードされ、施工範囲が設定されている。                                                                                                                                                                                                                                                                                     |
| 事後条件     | 庭オブジェクトの位置・向き・大きさ・個数が庭シミュレーション上に反映される。                                                                                                                                                                                                                                                                                             |
| 基本フロー    | 1. 利用者が設置したい商品を選ぶ。<br>2. 利用者が庭写真上の位置を指定して設置する。<br>      通信に失敗した場合は => 代替フロー2へ<br>3. システムが庭オブジェクトを庭シミュレーションに表示する。<br>      施工範囲の外に設置した場合は => 代替フロー1へ<br>4. 利用者が設置済みオブジェクトを選び、移動・回転・拡大縮小のいずれかを行う。<br>5. システムが操作結果を庭シミュレーションに反映する。<br>移動・拡大縮小で上限・下限を超える場合 -> 代替フロー3へ<br>6. 利用者が不要なオブジェクトを選び、削除する。<br>7. システムが庭オブジェクトを庭シミュレーションから取り除く。 |
| 代替フロー    | 1. 施工範囲の外に設置・移動した場合<br>1-1. システムが範囲外であることを表示し、範囲内への配置を促す。<br><br>2. 通信に失敗した場合(オブジェクト情報の取得など)<br>2-1. システムが通信エラーを表示し、再実行を可能にする。<br><br>3. 移動・拡大縮小で上限・下限を超える場合<br>3-1. システムが上限・下限の位置・大きさに制限する。                                                                                                                                       |
| 関連情報     | 商品と似たモデル(庭オブジェクト)が庭シミュレーション上に設置される。 / 商品と庭オブジェクトは1対1で紐づいている。                                                                                                                                                                                                                                                                       |

#### UC-06 完成イメージ画像を生成・保存する

| ユースケース概要 | 配置した庭オブジェクトを元の庭写真に重ねた、完成イメージ画像を生成して確認・保存する。                                                                                                                                                                                        |
| アクター     | 利用者(購入者)                                                                                                                                                                                                                           |
| 事前条件     | 庭シミュレーション画面が表示されている。庭オブジェクトが1つ以上配置されている。                                                                                                                                                                                           |
| 事後条件     | 完成イメージ画像が生成され、利用者が確認・保存できる状態になる。                                                                                                                                                                                                   |
| 基本フロー    | 1. 利用者が完成イメージの確認を選ぶ。<br>2. システムが配置情報(位置・向き・大きさ)を取得する。<br>3. システムが元の庭写真に庭オブジェクトを重ねて画像を生成する。<br>生成に失敗した場合は => 代替フロー1へ<br>4. システムが完成イメージ画像を表示する。<br>5. 利用者が必要に応じて、PNGで保存を選んで、完成イメージ画像をPNG形式で端末に保存(ダウンロード)する。<br>保存に失敗した場合は -> 代替フロー2へ |

#### UC-07 庭プロジェクトを保存する

| 記述項目     | 記述内容                                                                                                                                                                                                                                                                                                                                                                                      |
| -------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| ユースケース概要 | 庭オブジェクトの位置・個数・商品の情報を庭プロジェクトとして保存する。                                                                                                                                                                                                                                                                                                                                                       |
| アクター     | 利用者(購入者)                                                                                                                                                                                                                                                                                                                                                                                  |
| 事前条件     | 庭シミュレーション画面が開かれている。                                                                                                                                                                                                                                                                                                                                                                       |
| 事後条件     | 庭オブジェクトの位置・個数・商品の情報が保存され、次回以降に再開できる。                                                                                                                                                                                                                                                                                                                                                      |
| 基本フロー    | 1. 利用者が庭オブジェクトの配置・編集や施工範囲の修正・実寸定義の操作を行う。<br>      未ログイン状態の場合は => 代替フロー2へ<br>2. システムが庭オブジェクトの位置・個数・商品の情報を取得する。<br>3. システムが取得した内容を庭プロジェクトとして自動保存する。<br>      通信に失敗した場合は => 代替フロー1へ<br>4. システムが保存完了を表すアイコンを表示する。                                                                                                                                                                             |
| 代替フロー    | 1. 通信に失敗した場合<br>1-1. システムが通信エラーを表示し、保存されていないことを伝える。<br>1-2. システムが編集内容を保持したまま、再保存を可能にする。<br><br>2. 未ログイン状態の場合  <br>2-1. システムが自動保存を行わず、保存ボタンを表示する。  <br>2-2. 利用者が保存ボタンを選ぶ。  <br>2-3. システムがログイン画面を表示する。  <br>2-4. 利用者がログインすると、システムが編集内容を保持したまま基本フロー2へ進み、以降は自動保存を有効にする。  <br>      ログインを取り消した場合は => 代替フロー3へ  <br>  <br>3. ログインを取り消した場合  <br>3-1. システムが保存せずに庭シミュレーション画面に戻り、編集内容と保存ボタンの表示を維持する。 |
| 関連情報     | ログイン状態では自動保存、未ログイン状態では保存ボタンによる保存とする。 / 未ログイン時の編集内容は保存されないため、画面を閉じると失われる。 / 保存せず画面を閉じようとしたら「保存されていません」と警告メッセージを表示する。                                                                                                                                                                                                                                                                       |

#### UC-08 庭プロジェクトを管理する

| 記述項目     | 記述内容                                                                                                                                                                                                                                                                                           |
| -------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| ユースケース概要 | 作成した庭プロジェクトを一覧で確認し、複製して別案を作ったり、不要なプロジェクトを削除したりする。                                                                                                                                                                                                                                              |
| アクター     | 利用者(購入者)                                                                                                                                                                                                                                                                                       |
| 事前条件     | 利用者がログイン済みである。                                                                                                                                                                                                                                                                                 |
| 事後条件     | 複製した場合は新しい庭プロジェクトが追加され、削除した場合は対象が庭一覧から消える。                                                                                                                                                                                                                                                     |
| 基本フロー    | 1. 利用者が庭プロジェクト一覧画面を開く。<br>2. システムが利用者の庭プロジェクトを一覧表示する。<br>庭プロジェクトがない場合は => 代替フロー1へ<br>3. 利用者がプロジェクトを選び、操作(開く・複製・削除)を選ぶ。<br>4. 複製の場合、システムが選択したプロジェクトの内容を複製して新規プロジェクトを作成し、一覧に追加する。<br>5. 削除の場合、システムが削除の確認を表示する。利用者が確定すると、システムがプロジェクトを削除する。<br>利用者が削除を取り消した場合は => 代替フロー2へ<br>通信に失敗した場合は => 代替フロー3へ |
| 代替フロー    | 1. 庭プロジェクトがない場合<br>1-1. システムが新規作成(UC-01)を案内する。<br><br>2. 削除を取り消した場合<br>2-1. システムが削除せず、一覧表示に戻る。<br><br>3. 通信に失敗した場合<br>3-1. システムが通信エラーを表示し、再実行を可能にする。                                                                                                                                           |
| 関連情報     | 複製は別案の比較に使う / 削除したプロジェクトの復元はしない(要確認)                                                                                                                                                                                                                                                           |

#### UC-09 買い物リストを表示する

| 記述項目     | 記述内容                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| -------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| ユースケース概要 | 庭シミュレーション画面のサイドバーに、配置した庭オブジェクトに紐づく商品を買い物リストとして表示し、必要に応じてECの買い物リストを開く。                                                                                                                                                                                                                                                                                                                                                                         |
| アクター     | 利用者(購入者)                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| 事前条件     | 庭シミュレーション画面が表示されている。                                                                                                                                                                                                                                                                                                                                                                                                                          |
| 事後条件     | サイドバーに、配置中の庭オブジェクトに紐づく商品の一覧(商品画像、商品名、数量、小計)が表示される。                                                                                                                                                                                                                                                                                                                                                                                            |
| 基本フロー    | 1. システムが庭プロジェクトに配置されている庭オブジェクトとその個数を取得する。<br>      配置されたオブジェクトがない場合は => 代替フロー1へ<br>2. システムが各庭オブジェクトに紐づく商品の情報をECから取得する。<br>      紐づく商品が存在しない場合は => 代替フロー2へ<br>      通信に失敗した場合は => 代替フロー3へ<br>3. システムが商品ごとに、商品画像、商品名、数量(配置数)、小計(価格×数量)をサイドバーに 一覧表示する。<br>4. 利用者が庭オブジェクトを設置・削除した場合、システムが買い物リストの数量・小計を更新する。<br>5. 利用者がECの買い物リストを開くを選ぶ。<br>      未ログインの場合は => 代替フロー4へ<br>      庭プロジェクトが保存中の場合は => 代替フロー5へ<br>6. システムが対象の庭プロジェクトを指定して、ECの買い物リストを開く。 |
| 代替フロー    | 1. 配置されたオブジェクトがない場合<br>1-1. システムが買い物リストが空であることを表示し、オブジェクトの配置(UC-04)を案内する。<br><br>2. 紐づく商品が存在しない場合(商品の削除、紐づけ解除など)<br>2-1. システムがその庭オブジェクトに対応する商品がないことを一覧上に表示し、小計の計算から除外する。<br><br>3. 通信に失敗した場合<br>3-1. システムが通信エラーを表示し、再取得を可能にする。<br><br>4. 未ログインの場合<br>4-1. システムがログインを促す。ログイン後、基本フロー5へ戻る。<br><br>5. 庭プロジェクトが保存中の場合<br>5-1. ECの買い物リストを開くを選べないようにする。<br>5-2. 自動保存が完了したらECの買い物リストを開くを選べるようにする<br>5-3. 基本フロー5へ戻る。                                   |
| 関連情報     | 庭オブジェクトと商品は1対1で紐づく。 / 数量は配置されている庭オブジェクトの個数とする。 / Canvasの買い物リストからはカートへ追加できない(カート追加はEC側の買い物リストのみ)。                                                                                                                                                                                                                                                                                                                                              |
