# daily-report-cloud(日報スキルのクラウド用)

PCの `~/.claude/skills/daily-report` と同じ日報を、Anthropic のクラウドの定期実行(routine)で作るためのスキルです。PCの電源が切れていても、決まった時間に前日の日報を作り、`kusakari-document` の `main` にプッシュし、Artifact に公開します。
Claude への手順は `SKILL.md` に、ここには人が読むための使い方と設定を書いています。

## PCの daily-report との違い

| | PCの daily-report | daily-report-cloud |
|---|---|---|
| 置き場所 | `~/.claude/skills/daily-report`(PCだけ) | `kusakari-document/.claude/skills/daily-report-cloud`(GitHub に置く。クラウドはリポジトリの中のスキルしか読めないため) |
| 日報フォルダ | `config.json` の絶対パス | `kusakari-document` からの相対パス(`日報`) |
| 集めるリポジトリ | `config.json` の絶対パス | 定期実行がクローンした場所をスクリプトが探す(origin が `config.json` の `github` を指すフォルダ) |
| 履歴 | 手元のクローンのまま | 浅いクローン(shallow)でも、全部のブランチの全部の履歴を取ってから集める |
| ブランチ | `main` に乗っていなければ止まる | `claude/` のブランチなどで始まったら、コミットしていない変更が無ければ `main` に切り替える |
| コミットするもの | 日報フォルダだけ | 日報フォルダと、このスキルの `config.json`(新しい年の Artifact の URL を残すため) |
| 呼び出し時の文章(手入力) | 書ける | 定期実行では書かない(前の版の手入力は引き継ぐ) |
| yomiyasu での推敲 | する | クラウドに yomiyasu が無ければ飛ばし、報告にそう書く |
| 止まったとき | 利用者に聞く | 待たずに止まり、定期実行の記録に理由を書く |

ページのひな形(`template/`)と、集め方・判定・検査・組み立ては PCの daily-report と同じです。PCの daily-report のひな形やスクリプトを直したときは、こちらにも同じ変更を入れてください。`lib.mjs`・`collect.mjs`・`sync.mjs`・`commit.mjs` はクラウド用に直してあるので、上書きせずに差分だけを移します。

## 使い方

定期実行(https://claude.ai/code/routines)に次の設定で登録します。

| 項目 | 値 |
|---|---|
| リポジトリ | `abeouga/kusakari-document`・`abeouga/kusakari-canvas`・`abeouga/kusakari-ec` の3つ |
| 時刻 | 毎日 04:00(日本時間)。1日の区切りが 03:00 なので、それより後にする。UTC の cron なら `0 19 * * *` |
| モデル | Claude Opus 5.5(PCの daily-report の README の「推奨のモデルとエフォート」と同じ考え) |
| 環境 | Default(ネットワークは Limited のままでよい) |
| 指示 | 下の文 |

```
/daily-report-cloud
このスキルが見つからないときは、クローンされた kusakari-document の .claude/skills/daily-report-cloud/SKILL.md を読み、その手順に従って前日の日報を作ってください。
日報は kusakari-document の main に直接プッシュします。claude/ のブランチやプルリクエストは作りません。
```

- 日付を指定して作り直したいときは、定期実行の画面から「今すぐ実行」するのではなく、PCの daily-report で `/daily-report 2026-11-12` を呼ぶか、指示を `/daily-report-cloud 2026-11-12` にした1回だけの実行を作ります。
- PCの daily-report とこのスキルは、同じ日報フォルダと同じ Artifact に書きます。毎日の分はクラウドに任せ、PCの daily-report は作り直しや手入力の訂正にだけ使ってください。同じ日付を両方で作ると、あとから作ったほうで上書きされます。
- PCで作業するときは、先に `kusakari-document` で `git pull` をしてください。クラウドが毎日 `main` にプッシュしています。

## まだ確かめていないこと(クラウド)

- 3つのリポジトリをクローンしたときに、`kusakari-document` の `.claude/skills` のスキルが読み込まれるか。読み込まれないときのために、指示で SKILL.md を直接読むよう書いています。
- クラウドのセッションから、PCで作った Artifact(`config.json` の `artifacts`)を更新できるか。できなかったときは公開を飛ばし、報告に書きます。
- `main` にプッシュできるか。GitHub 側で `main` を保護している(ブランチの保護ルール)と断られます。

## できるもの

| 場所 | 中身 |
|---|---|
| `kusakari-document/日報/index.html` | ブラウザで開く日報。コメント欄は出ません。クラウドで作った日報は、PCで `git pull` をすると手元に来ます |
| `kusakari-document/日報/json/<日付>.json` | 1日分の元データ。検索や作り直しに使います |
| `kusakari-document/日報/data/` | ページが読み込むデータ(`index.js` が日付の一覧、`<日付>.js` が1日分) |
| Artifact(claude.ai 上のページ) | 同じ日報。コメント欄が使えます。年ごとに1つ |

Obsidian はアプリの中でHTMLを表示できません。`index.html` はブラウザで開いてください。

## 設定(`config.json`)

| 項目 | 意味 |
|---|---|
| `boundary` | 1日の区切りの時刻。初期値は `03:00` |
| `utcOffset` | 時差。日本時間は `+09:00` |
| `outputDir` | ローカルの保存先(`kusakari-document/日報`) |
| `repos` | 集めるリポジトリ。`path` はフォルダの絶対パス(スキルをどこに置いても同じ場所を指すようにするため)、`github` は GitHub 上の名前、`prefix` は項目IDの頭に付く短い名前 |
| `artifacts` | 年ごとの公開先URL。下の「公開先URLの保存」を参照 |
| `git` | 日報フォルダの取り込み・コミット・プッシュの設定。下の「最初の取り込み」と「コミットとプッシュ」を参照 |
| `limits` | 収集するときに本文やコメントを切る文字数 |

`prefix` は途中で変えないでください。過去の日報と項目ID(`ec-issue-130` など)の付け方が揃わなくなります。

## 公開先URLの保存

別の日に呼んだときも同じ Artifact に追加できるよう、公開先のURLを `config.json` の `artifacts` に年ごとに保存します。

- その年で初めて公開したとき、スキルが次のコマンドで自動的に保存します。
  ```bash
  node "${CLAUDE_SKILL_DIR}/scripts/set-artifact.mjs" 2026 https://claude.ai/artifact/xxxx
  ```
- 手で直すときは、`config.json` を次の形にします。
  ```json
  "artifacts": { "2026": "https://claude.ai/artifact/xxxx" }
  ```
- URLを消すと、次の呼び出しで新しい Artifact が作られます(前の Artifact とコメントは残りますが、別のページになります)。
- 年が変わると、新しい年の Artifact が自動で作られます。1つの Artifact に置けるファイルは約500個までで、1年分(約370個)が収まるためです。新しい Artifact は、メンバーをもう一度招待する必要があります。

## コメント欄を使うための共有

Artifact は、公開した直後は自分だけが見られる状態です。メンバーがコメントを書くには、claude.ai のページ右上の共有メニューから招待します。

- メンバーは claude.ai のアカウントでサインインしている必要があります。
- 個人のプランでは、コメントを書き込めるのは **「編集者」として招待された人** です。閲覧だけの招待では、読めますが書けません。
- 公開リンクでの共有を同時に有効にすると、招待した編集者も書き込めなくなります。公開リンクは使わないでください。
- 編集者はページ自体を作り変えることもできます。信頼できるメンバーだけを招待してください。
- 名前が表示されない人のために、コメント欄には「表示名」の入力欄が出ます。

コメントの決まり:

- コメント欄は2種類あります。各項目の下の「コメントする」ボタンで開く欄は、その項目について書きます。ページ下の「この日の会話」は、その日の日報全体について書きます。
- コメント欄は、上から、書き込む欄、並び順のボタン、コメントの一覧の順に並びます。
  - 並び順は「新しい順」と「古い順」から選べます。最初は「新しい順」です。ボタンは、コメントが2件以上ある欄に出ます。
  - 選んだ並び順は、すべてのコメント欄に効きます。その人のブラウザに覚えておくので、次に開いたときも同じ順です。ほかの人の画面や、別の端末には影響しません。
- コメントには画像を4枚まで付けられます。「画像を付ける」ボタンで選ぶか、入力欄に貼り付けるかドラッグで置きます。PNG・JPEG・GIF・WebP で、1枚20MBまでです。画像だけのコメントも書けます。
  - 大きい画像は、長い辺が1600pxになるよう縮めてから保存します(GIF はそのまま)。
  - 画像を付けられるのは「編集者」として招待された人だけです。
  - Android の Claude アプリでは、「画像を付ける」を押しても画像を選ぶ画面が開きません(アプリの中のブラウザが対応していないため。2026-11-15 に Pixel 9 で確認)。アプリで開いたときは、その旨の案内がコメント欄に出ます。Chrome で claude.ai を開くと付けられます。iPad のアプリでは付けられました。iPhone のアプリは試していません。
  - 画像を押すと大きく表示されます。
  - コメントを削除すると、付けた画像も消えます。元には戻せません。
  - 画像は Artifact ごとに保存され、保存できる量には上限があります。上限に達すると「上限に達しています」と出ます。
- 「要確認」の項目は、コメント欄の「要確認を外す」ボタンで外せます。
  - 外す理由を入力欄に書いてから押します。理由はコメントとして残り、「要確認を外した」の印が付きます。
  - 外すと、項目の「要確認」が「確認済み」に変わり、日付の一覧の「要確認」の数も減ります。「確認済み」に指を置く(マウスを重ねる)と、外した人の名前が出ます。
  - 「要確認を外した」コメントをすべて削除すると、「要確認」に戻ります。コメントを編集しても状態は変わりません。
  - 変わるのはページの表示だけです。日報のデータの判定は「要確認」のままで、作り直しても変わりません(Claude はコメントを読まないため)。項目のIDは作り直しても同じなので、外した状態は残ります。
  - 手元の `index.html` にはコメント欄が無いので、「要確認」のまま表示されます。
- 日報を作り直して項目が消えたときは、その項目へのコメントは「この日の会話」に、どの項目へのコメントだったかを添えて出ます。
- 編集できるのは自分のコメントだけです。削除は自分のコメントと、Artifact の持ち主ならすべてのコメントができます(画面上の制限です。編集者はデータを直接書き換えられる立場にあります)。
- まだ読んでいないコメントには「新着」の印が出ます。
  - 印が出る場所は4つです。ページの上の「新着コメント」の一覧、日付の一覧、項目の「コメント」ボタンの横、コメントそのものです。
  - 「新着コメント」の一覧は、日をまたいで新しい順に10件まで並びます。行を押すと、その日のその項目のコメント欄が開きます。
  - 既読になるのは、項目のコメント欄を開いたときと、「この日の会話」が画面に入ったときです。「すべて既読にする」ボタンでも既読にできます。
  - 既読にしたコメントの「新着」の印は、ほかの日に移るかページを開き直すまで残ります。どれが新しかったかを読みながら確かめられます。
  - 自分のコメントには印が出ません。2026-11-16 より前のコメントは、全員にとって既読として扱います。
  - どこまで読んだかは、Artifact のデータの保存先に人ごとに残ります。パソコンとスマートフォンのどちらで読んでも、既読がそろいます。この記録は本人だけが読み書きでき、ほかのメンバーや Artifact の持ち主からは見えません。
  - 閲覧だけの招待の人は既読を残せないので、印は出ません。
- 通知は飛びません。新着が分かるのは、ページを開いたときだけです。日付の一覧にはコメントの件数も出ます。
- Claude はコメントを読みませんし、日報にも反映しません。コメントはメンバーどうしの会話のためのものです。SKILL.md で、Claude がこの Artifact のデータ保存先やコメントを読むことを禁じています。訂正したいときは、項目の「関連issue」から GitHub にコメントを書いてください。次の日報で拾われます。その日の日報をすぐ直したいときだけ、呼び出し時に訂正の文章を書きます。

## 仕組み

1. `scripts/sync.mjs` が、`kusakari-document` のリモートに日報フォルダの新しい変更があるかを確かめ、あれば `git pull` で取り込みます。
2. `scripts/collect.mjs` が、各リポジトリで `git fetch` をしてから、その日のコミット・issue・PR・コメントを集めます。コメントは更新日時で拾うので、編集による訂正も入ります。
3. Claude が集めた内容を読み、提案か確定かを文面から判定して、日報の中身を JSON で書きます。
4. `scripts/build.mjs` が JSON を検査します。IDが実在するか、必須の項目があるか、前の版の手入力が消えていないかを確かめ、問題があれば何も書き出しません。リンク先のURLは、Claude ではなくこのスクリプトがIDから付けます。
5. 検査を通ると、ローカルと公開用のファイルが書き出され、Claude が Artifact に公開します。
6. `scripts/commit.mjs` が、日報フォルダの変更をコミットしてプッシュします。

ページの見た目と処理は `template/`(`page.html`・`app.css`・`app.js`)に固定で持っています。毎日 Claude が書くのはデータだけです。

見た目は、デジタル庁デザインシステムの色・書体・部品の形に寄せています。

- 明るい表示と暗い表示があり、パソコンやスマートフォンの明暗の設定(claude.ai 上では claude.ai の設定)に合わせて切り替わります。
- デジタル庁デザインシステムには暗い表示の色の決まりが無いので、暗い表示の色は同じ色の濃淡から選んでいます。
- 色は `page.html` の先頭で、「ページの地」「文字」「リンク」のような役割の名前に値を割り当てています。`app.css` はこの名前だけを使うので、色を変えるときは `page.html` の明るい表示と暗い表示の値を直します。暗い表示の値は2か所(端末の設定に合わせる所と、claude.ai で暗い表示を選んだ所)に同じものを書いているので、両方を直してください。

| ファイル | 役割 |
|---|---|
| `SKILL.md` | Claude への手順 |
| `config.json` | 設定 |
| `scripts/sync.mjs` | 日報フォルダにリモートの新しい変更があれば取り込む |
| `scripts/collect.mjs` | 集める |
| `scripts/show.mjs` | 集めた中から1件の全文を表示する |
| `scripts/build.mjs` | 検査して組み立てる |
| `scripts/set-artifact.mjs` | 公開先URLを保存する |
| `scripts/commit.mjs` | 日報フォルダをコミットしてプッシュする |
| `template/` | ページのひな形 |
| `work/` | 集めた結果と Claude が書いた JSON(作業用) |
| `publish/<年>/` | Artifact に公開するファイル |

## 最初の取り込み

日報を作り始める前に、`kusakari-document` のリモート(GitHub)を確かめます。
日報フォルダに新しい変更があれば、`git pull` で取り込んでから日報を作ります。

- 取り込むのは、リモートの新しいコミットが日報フォルダ(`outputDir`)の中を変えているときだけです。日報フォルダの外だけが変わっているときは、取り込みません。
- 取り込むときは、`git pull` の仕組み上、同じコミットに入っているほかのファイルの変更も一緒に入ります。
- 手元にプッシュしていないコミットが無ければ、`git pull --ff-only` で取り込みます。日報フォルダの外に書きかけの変更があっても、取り込むファイルと重ならなければ、そのまま残ります。
- 手元にプッシュしていないコミットがあるときは、コミットしていない変更が無いときだけ、`git pull --rebase` で取り込みます。
- 先に取り込むのは、前の版の手入力と日付の一覧を、最新のファイルから作るためです。

取り込めなかったとき:

- 何も変えずに、日報を作る前に止まり、理由と、することを知らせます。古いファイルの上に日報を作ると、最後のプッシュでぶつかるためです。
- 止まるのは、次の場合です。
  - 手元のコミットしていない変更が、取り込むファイルと重なっている
  - 手元のプッシュしていないコミットが、リモートの変更とぶつかった
  - `git.branch` と違うブランチにいる
  - GitHub につながらない
- クラウドでは止まったまま終わり、定期実行の記録に理由が残ります。PCで `git pull` などをして直してから、次の回を待つか、1回だけの実行を作ってください。
- `config.json` の `git.autoPull` を `false` にすると、リモートを確かめずに作り始めます。

## コミットとプッシュ

日報を作ると、最後に `kusakari-document` の日報フォルダが自動でコミットされ、プッシュされます。

- コミットするのは日報フォルダ(`outputDir`)の中だけです。同じリポジトリのほかのファイルは、書きかけの変更があっても入りません。
- コミットメッセージは「2026/11/14の日報を追加」の形です。その日の日報がすでにコミットされていれば「…を更新」になります。
- いまのブランチにコミットし、GitHub の同じ名前のブランチにプッシュします。強制プッシュはしません。
- プッシュでは、手元の同じブランチにある、まだプッシュしていないほかのコミットも一緒に送られます(git の仕組み上、日報のコミットだけを選んで送ることはできません)。
- 日報フォルダに変更が無ければ、何もしません。
- 日報を作らずにひな形だけを直したときは、日付の代わりに件名を渡してコミットします(`node "${CLAUDE_SKILL_DIR}/scripts/commit.mjs" --message "<件名>"`)。

`config.json` の `git` で動きを変えられます。

| 項目 | 意味 |
|---|---|
| `autoPull` | `false` にすると、最初の取り込みをしません |
| `autoCommit` | `false` にすると、コミットもプッシュもしません |
| `autoPush` | `false` にすると、コミットだけして、プッシュはしません |
| `branch` | 取り込みとコミットをしてよいブランチ。いまのブランチがこれと違うと、何もせずに知らせます。消すと、どのブランチでも行います |

プッシュできなかったとき:

- ほかの人が先にプッシュしていた場合は、リポジトリにコミットしていない変更が無ければ、`git pull --rebase` で取り込んでから1回だけやり直します。
- コミットしていない変更があるときや、取り込みでぶつかったときは、何もせずに知らせます。コミットは手元に残っているので、`git pull --rebase` をしてから `git push` をしてください。
- 鍵のパスフレーズなどを聞かれる設定のときは、待たずに失敗します。そのときは手で `git push` をしてください。

## 提案と確定の分け方

- 確定: main にマージされた、完了として閉じられた、または文面に決定と書かれているもの
- 提案中: 開いている issue や PR で、まだ決まっていないもの
- 作業中: ブランチにだけあるもの
- 取り下げ: 対応しないとして閉じられたもの

確定した仕様のうち、同じ日に実装も入ったものは「確定した仕様」には出さず、「変更内容」に「仕様確定」の印を付けて、決まったことと実装を1項目にまとめます。日付の一覧の「確定」の数には、これも入ります。

「要確認」は、決まったのか文面から読み取れないときや、書かれていることどうしが矛盾しているときに付きます。判定理由が項目ごとに1行出ます。

## 必要なもの

- クラウドの環境には Node.js・git・`gh` が最初から入っています。`gh auth login` は要りません(GitHub への通信は専用の中継を通り、定期実行に追加したリポジトリだけを読み書きできます)。
